# Claude Code 프롬프트 모음 — 해 지기 전에 (Before Sundown) · 고정 카메라 3D

## 사용 방법

1. 저장소(`astruelds/before-sundown`)에 아래 세 파일이 들어가야 한다. 처음 한 번 "시작 메시지"로 넣는다.
   - `CLAUDE.md` (저장소 맨 위): 작업 규칙과 핵심 시스템
   - `docs/story.md`: 전체 이야기
   - `docs/game_data.md`: 무기, 아이템, 캐릭터, 동물, 장소별 파밍 등 목록과 수치
2. 아래 프롬프트를 **번호 순서대로 하나씩** 복사해서 붙여 넣는다.
3. 한 단계가 끝날 때마다 Claude가 커밋하고 푸시하면, **GitHub Desktop에서 Pull → Godot에서 실행해 확인 → 결과를 Claude에게 알려 주기** 후 다음 단계로 간다.
4. 내가 Godot에서 맵을 칠하거나 배치를 바꿨으면 **Commit → Push**로 올리고 Claude에게 알려 준다.
5. 막히면 맨 아래 "자주 쓰는 프롬프트"를 쓴다.

---

```
저장소는 astruelds/before-sundown 이야.
첨부한 세 파일을 이렇게 넣어 줘:
- CLAUDE.md → 저장소 맨 위

- game_data.md → docs/game_data.md

그다음 CLAUDE.md를 끝까지 읽고, docs/ 두 문서도 훑어봐 줘.
이미 만들어 둔 0단계 파일이 있으면 CLAUDE.md 기준과 다른 점이 없는지 확인하고 맞춰 줘.
아직 Godot 프로젝트가 없으면 새로 만들어 줘:
- 내 컴퓨터의 Godot 버전은 [여기에 버전 번호] 이야
- 렌더러 Forward+, 프로젝트 이름 Before Sundown

그리고 세 문서를 읽고 이해한 내용을 다섯 줄로 요약해 줘. 내가 잘 전달됐는지 확인할게.

## 0단계. 프로젝트 준비

### 0-1. 프로젝트 확인과 설정

```
CLAUDE.md를 먼저 읽어 줘.
그다음 이 Godot 프로젝트의 현재 상태를 확인하고, CLAUDE.md의 "4. 기술 사양"대로 project.godot 설정을 맞춰 줘.
(렌더러 Forward+ 확인, 창 1920x1080, Stretch canvas_items + expand)

그리고 물리 레이어(Layer Names > 3D Physics) 이름을 정해 줘: world(벽, 바닥), player, zombie, props(숨을 곳, 물건), cover(낮은 엄폐물).
레이어가 무엇이고 왜 이름을 붙여 두면 좋은지 쉽게 설명해 줘.
내가 에디터에서 직접 확인해야 할 설정이 있으면 메뉴 경로와 함께 알려 줘.
```

### 0-2. 폴더 구조와 Git

```
CLAUDE.md의 "6. 폴더 구조"대로 폴더를 만들어 줘.
그리고 Godot 프로젝트용 .gitignore를 만들고, Git 저장소를 초기화한 다음 첫 커밋을 해 줘.
Git이 처음이라서, 앞으로 내가 알아야 할 Git 명령어 3~4개(상태 보기, 커밋, 직전 상태로 되돌리기)를 쉽게 정리해 줘.
3D 모델 파일은 용량이 클 수 있는데, Git으로 관리할 때 주의할 점이 있으면 알려 줘.
```

### 0-3. Input Map

```
CLAUDE.md의 "5. 조작" 표대로 Input Map 액션을 project.godot에 등록해 줘.
등록한 뒤, 에디터의 Project > Project Settings > Input Map에서 어떻게 확인하는지 알려 줘.
```

### 0-4. Autoload 뼈대

```
CLAUDE.md의 "8. Autoload" 표에 있는 GameState, NoiseBus, SceneRouter를 scripts/autoload/ 에 만들고 Autoload로 등록해 줘.
지금은 1차 최소 버전에 필요한 것만 넣어 줘:
- GameState: energy(최대 5), has_wound, coins, held_weapon, looted_ids(털린 물건 목록), hide_spot_remaining(숨을 곳별 남은 시간), flags
- NoiseBus: signal noise_made(position: Vector3, radius: float, global: bool) 과 그 신호를 보내는 함수 make_noise()
- SceneRouter: 씬 전환 함수와 "어느 문으로 들어왔는지" 저장

DialogueManager는 아직 만들지 마.
Autoload가 무엇인지, 왜 전역으로 두는지 쉽게 설명해 줘.
```

### 0-5. 다국어 기초 (한국어, 영어)

```
CLAUDE.md의 "다국어" 항목대로 한국어/영어 전환의 기초를 만들어 줘. 처음부터 해 두면 나중에 글자를 다시 고칠 필요가 없으니까.
- data/translations/ui.csv 를 keys,ko,en 형식으로 만들고 Project Settings > Localization에 등록
- Settings Autoload: 언어를 user://settings.cfg에 저장하고 불러오기, 처음 실행 때는 컴퓨터 언어를 따라가기(한국어가 아니면 영어), set_language("ko"/"en") 함수로 바로 바꾸기
- 테스트용 간단한 설정 화면: "언어 / Language" 선택(한국어, English), 고르면 화면 글자가 바로 바뀜
- 한국어 조사 자동 선택 함수: 이름의 마지막 글자 받침을 보고 이/가, 을/를, 은/는, 와/과 중 맞는 것을 고름 (예: "서하람이", "강도윤이" / "지아가")
- 앞으로 UI 글자를 추가하는 방법(키 이름 짓는 규칙, csv에 한 줄 추가)을 알려 줘

tr() 함수와 번역 키가 무엇인지 쉽게 설명해 줘.
```

## 1단계. 시제품과 1차 최소 버전

### 1-1. 테스트 방

```
3D 테스트 방을 만들어 줘. 모델이 아직 없으니 기본 도형으로.
- scenes/levels/test_room.tscn
- 바닥(20m x 20m), 벽 몇 개로 복도 하나와 방 두 개, 문 자리 하나
- 낮은 상자 몇 개(높이 0.8m, 엄폐물용)와 책상 하나
- 모두 StaticBody3D + CollisionShape3D, 물리 레이어는 world 또는 cover
- NavigationRegion3D로 좀비가 걸어 다닐 길을 굽기(bake)
- 지붕은 없음, 화면 아래쪽(카메라 쪽) 벽은 높이 1m로 낮게

3D 좌표(X, Y, Z 축)가 각각 어느 방향인지, StaticBody3D와 CollisionShape3D가 무엇인지 쉽게 설명해 줘.
내비게이션을 다시 굽는(bake) 방법도 알려 줘.
```

### 1-2. 플레이어 이동과 마우스 조준

```
scenes/player/ 에 플레이어 씬을 만들어 줘.
- CharacterBody3D, 높이 1.4m 정도의 캡슐 모양(임시), 머리 위치를 표시하는 Marker3D(head_point)
- WASD로 바닥 평면(X-Z)에서 8방향 이동, 화면 기준 방향, 대각선 속도 보정
- Shift를 누르고 있으면 살금살금 걷기 (느려짐, is_sneaking)
- 마우스 조준: 카메라에서 마우스 위치로 광선을 쏴서 Y=0 바닥 평면과 만나는 점을 구하고, 캐릭터가 그쪽을 바라봄 (Y축 회전만)
- 중력은 적용하되 점프는 없음
- 속도 값은 @export

테스트 방에 플레이어를 놓아 줘. 마우스 조준의 원리(광선과 평면)를 그림 그리듯 쉽게 설명해 줘.
```

### 1-3. 고정 카메라와 벽 투명 처리

```
scenes/camera/ 에 고정 카메라를 만들어 줘.
- 위에서 비스듬히 내려다보는 Camera3D (기울기, 거리, 시야각 @export: 기본 55도, 12m, 40도)
- 플레이어를 부드럽게 따라가지만 회전은 절대 하지 않음
- 카메라와 플레이어 사이에 벽이나 큰 물체가 있으면 그 물체를 반투명하게 (광선 검사, 떨어지면 원래대로)
- 테스트: 벽 뒤로 걸어가도 캐릭터가 보이는지

카메라 값을 바꿔 가며 마음에 드는 각도를 찾는 방법을 알려 줘.
```

### 1-4. 어둠과 휴대폰 불빛

```
밤 구간의 어둠과 휴대폰 불빛을 만들어 줘.
- WorldEnvironment: 주변광 아주 어둡게(윤곽만 흐릿하게 보일 정도), 배경 검정, 채도 낮게 — 값은 @export나 Environment 리소스로 조절
- 플레이어에게 휴대폰 불빛 SpotLight3D: 마우스 조준 방향, 손 높이(약 1m)에서 비춤, 그림자 켬, 따뜻한 색
- F키로 불빛 켜기/끄기 (is_light_on)
- 벽 뒤가 어둡게 남는지 확인
- 비상구 표시등처럼 쓸 초록색 작은 OmniLight3D 예시 하나

SpotLight3D의 범위(range), 각도(spot angle), 감쇠가 각각 무엇인지 설명해 줘.
```

### 1-5. 소리 신호와 바닥 물건

```
scenes/props/ 에 바닥 물건 씬(floor_clutter.tscn)을 만들어 줘.
- Area3D + 작은 메시(임시 도형), 종류(캔/유리/병)를 @export로
- 종류마다 소리 범위(미터)가 다름 — 캔 4, 유리 6, 병 9 (@export)
- 플레이어가 밟으면 AudioStreamPlayer3D로 소리(파일이 없으면 print로 대신) + NoiseBus.make_noise()
- 살금살금 또는 웅크린 상태면 소리 범위 절반
- 병은 한 번 밟으면 깨져서 사라짐
- 휴대폰 불빛 안에 들어오면 작게 반짝임 (불빛 방향과 각도, 사이에 벽이 있는지 검사)

테스트 방에 몇 개 놓는 방법과 확인 방법을 알려 줘.
```

### 1-6. 좀비 기본 (순찰, 소리 추적, 수색)

```
scenes/zombies/ 에 좀비 씬을 만들어 줘. 이번 단계에서는 "보기"는 빼고 "듣기"만.
- CharacterBody3D + NavigationAgent3D, 임시로 초록 캡슐 + 머리 위 표시용 Label3D(항상 카메라를 향함)
- 상태: enum State { PATROL, INVESTIGATE, SEARCH } 와 match 문으로 나누기
- PATROL: Path3D 경로를 따라 천천히 걷기 (경로는 에디터에서 내가 그림 — 그리는 방법 알려 줘)
- NoiseBus 신호를 받으면 범위 안일 때 INVESTIGATE, 소리 난 곳으로 이동
- 도착하면 SEARCH: 주변을 6~10초 서성이다가 PATROL로 돌아감
- 머리 위 "?" 표시 (INVESTIGATE, SEARCH)
- 속도, 시간 값은 @export

enum과 match가 무엇인지, 상태를 나누면 왜 좋은지 설명해 줘.
```

### 1-7. 좀비 시야, 추격, 웅크리기

```
좀비에게 "보기"를 추가하고, 플레이어에게 웅크리기를 추가해 줘.
좀비:
- 바라보는 방향 기준 부채꼴 시야 (각도, 거리 @export)
- 좀비 눈 높이에서 플레이어의 head_point로 광선을 쏴서 world/cover 레이어에 막히면 못 봄
- 플레이어 불빛이 켜져 있으면 시야 거리 증가
- 보면 CHASE: 머리 위 "!", 쫓아감 / 놓치면 마지막 위치로 가서 SEARCH
- 디버그용 시야 부채꼴 표시 옵션(@export 체크박스)
플레이어:
- 숨을 곳이 아닌 곳에서 C → 웅크리기 토글: 느려짐, 소리 작아짐, head_point 높이가 낮아짐(예: 1.3m → 0.6m), 캡슐도 낮아짐

테스트: 낮은 상자 뒤에 웅크려서 좀비가 지나가는지 확인하는 방법.
```

### 1-8. 숨을 곳과 숨 참기 (사물함)

```
scenes/props/ 에 숨을 곳 씬(hide_spot.tscn)을 만들어 줘. 먼저 사물함 하나로.
- @export: hide_time(기본 20), spot_id(고유 이름), 종류
- 가까이에서 C → 플레이어가 사물함 안 위치(Marker3D)로 들어가고 문이 닫힘(문 메시 회전 애니메이션), 불빛 자동 꺼짐, 이동 정지
- 화면 가장자리에 사물함 틈 모양의 어두운 테두리(UI)
- 들어가는 순간 그 플레이어를 보고 있던 좀비가 있으면 실패 (좀비가 사물함으로 옴)
- 숨어 있으면 좀비 시야 검사에서 제외
- 숨을 곳 위에 남은 초와 게이지 (Label3D 또는 화면 UI)
- 시간이 다 되면 "푸하!" 하고 튀어나오고 사물함은 회색 재질로 바뀌어 다시 못 씀
- 중간에 C로 나오면 남은 시간 유지 (GameState.hide_spot_remaining[spot_id])
- 끝까지 다 쓰고 나오면 2초 헐떡임 + 작은 소음
- 사물함은 어둠 속에서도 테두리가 희미하게 보이게 (약한 발광)
```

### 1-9. 심장 소리

```
숨어 있을 때 심장 소리 연출을 추가해 줘.
- 남은 숨이 줄수록 박동 간격이 짧아짐
- 가장 가까운 좀비와의 거리가 가까울수록 소리가 커짐
- 화면 가장자리가 박동에 맞춰 어두워지는 효과 (소리를 꺼도 알 수 있게), 남은 3초에는 붉게
소리 파일이 없으면 임시 비프음이나 print로 대신하고, 나중에 파일만 바꿔 끼우면 되게 해 줘.
```

### ★ 시제품 점검 (3D로 계속 갈지 판단)

```
지금까지 만든 3D 시제품을 점검해 줘.
1. 에러나 경고가 있는지
2. 내가 직접 플레이하면서 확인할 체크리스트 (숨기, 시야, 불빛, 카메라, 소리)
3. 2D로 만들었을 때와 비교해서, 지금 구조에서 앞으로 특히 어려워질 부분(모델, 애니메이션, 맵 만들기 등)과 그 대처 방법
4. 다음 단계로 가기 전에 정리하면 좋은 코드
고칠 것이 있으면 목록으로 먼저 보여 주고, 내가 고르면 하나씩 고쳐 줘.
```

### 1-10. 좀비 공격, 에너지, 게임오버

```
좀비 공격과 플레이어 에너지를 만들어 줘.
- 좀비가 가까우면 팔을 드는 예고 동작 0.5초 → 휘두르기 (그 순간에만 켜지는 공격 판정 Area3D)
- 맞으면: 에너지 1 감소, 1초 무적(깜빡임), 뒤로 밀림, has_wound = true
- 에너지가 1일 때 맞으면: "기절" 게임오버 화면 (좀비 "냠!", 별 빙글빙글 — 지금은 글자로)
- 게임오버 화면에서 "다시 시작" 버튼
- HUD(CanvasLayer): 화면 왼쪽 위 하트 5칸, 에너지 1칸이면 화면 가장자리가 붉게
```

### 1-11. 무기 (야구배트)

```
무기 시스템의 기초를 만들어 줘.
- resources/weapons/ 에 WeaponData Resource:

```

## 3단계. 이야기와 마무리

### 3-0. 장(맵) 만들기 — 장마다 반복해서 쓰는 프롬프트

> [ ] 부분만 바꿔서 1장부터 10장, 우회 장까지 하나씩 만든다. 한 장이 크면 장소별로 나눠서 요청한다.

```
[2장 대학가 골목]을 만들 거야. docs/story.md의 [2장] 부분과 docs/game_data.md를 보고 진행해 줘.

1. 먼저 이 장의 설계안을 표로 보여 줘 (아직 만들지 말고):
   - 장소 목록과 대략적인 배치 (시작 지점 → 끝 지점)
   - 낮/밤, 시작 시각
   - 좀비 종류와 수, 순찰 경로 아이디어
   - 숨을 곳, 바닥 물건, 엄폐물 위치 아이디어
   - 파밍 (game_data "19. 장소별 파밍")
   - NPC, 동물 동료, 신호 지점, 쉼터, 잠긴 곳
   - 이 장에서 처음 배우는 기믹과 연출 장면 (story "핵심 규칙 연출 장면")
   - 다음 장으로 가는 출구 (갈림길이면 출구마다 다음 씬)
2. 내가 설계안을 확인하면, 씬 틀을 만들어 줘: 바닥과 벽(임시 도형 또는 에셋), 내비게이션, 카메라, 어둠/햇빛 설정, 이벤트 트리거, 출구
3. 모델을 배치하거나 맵을 다듬는 일은 내가 할 테니, 어디에 무엇을 놓으면 좋은지 목록으로 알려 줘
4. 이 장의 대사와 카톡, 메모를 dialogue.json에 ko/en으로 추가해 줘
```

```
핵심 규칙 연출 장면을 쉽게 만들 수 있는 공통 틀을 만들어 줘.

```

```
갈림길과 엔딩 판정을 만들어 줘.

- 본 엔딩과 동물 도감을 user:// 에 저장, 타이틀 화면의 엔딩 목록에서 확인
